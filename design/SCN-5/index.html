SLAY CITY Native UI components

Text, button, card, input, screen container and pressable — every state, taken from the web app's own source at rubanwd/slay-city@7612da5, not estimated from screenshots. Dark only, like the product. Units are React Native points; web pixels map one to one. The same values are in machine-readable form in <script id="slay-ui-spec"> at the top of this file.

Before you implement

Nine places where the SCN-5 prompt and the web app disagree. The web app wins in each; here is why.

D1 · Colour scheme

Prompt saysSupport dark mode via NativeWind's scheme detection; design light and dark modes.

Do insteadDark only. Do not implement a light palette, `dark:` variants or colour-scheme detection.

The web app has no light theme anywhere — no `dark:` variant, no prefers-color-scheme rule. AGENTS.md makes #111111 the base. This repo already agrees: app.json sets userInterfaceStyle "dark" and tailwind.config.js sets darkMode "class" because "the app is dark-only".

D2 · Button variant names

Prompt saysButton (primary, secondary, tertiary).

Do insteadKeep the web's names: variant "pink" | "green" | "ghost", default "pink". Keep sizes "sm" | "md" | "lg", default "md", and the loading, iconLeft, iconRight props.

WP-1.3 AC1: every web variant exists under the same prop name, so ported screens stay greppable against upstream. By usage, green is the everyday call to action (70 of 128 buttons), ghost the secondary (35), pink the accent (23) — do not remap them onto primary/secondary/tertiary.

D3 · Palette size

Prompt saysUse the six brand colours.

Do insteadSeven tokens: neon-pink, lime-green, cyan, purple, neon-orange, black, white. Plus the neutral `surface` #1A1A1A, added to packages/tokens alongside this document.

AGENTS.md lists seven. `surface` is the web SlayCard background, which upstream writes as a raw bg-[#1a1a1a]; naming it keeps raw hex out of this repo.

D4 · NativeWind preset

Prompt saysExport a shared preset file for NativeWind configuration (tailwind.config.js in the root).

Do insteadIt exists. Extend packages/tokens/preset.js, which tailwind.config.js already consumes. Do not create a second preset.

Built in WP-0.1; one preset is what keeps a className and a StyleSheet from drifting apart.

D5 · Medium button height

Prompt says(not mentioned)

Do insteadmd is 52pt tall.

The web asks for h-13 (3.25rem = 52px), but h-13 is not in Tailwind 3's spacing scale and generates no CSS, so the 49 md buttons in production render at their 24px line height. 52 is the evident intent; 24 would also break the 44pt minimum touch target. This is a web bug, not a design.

D6 · Ripple feedback

Prompt saysPressable with ripple feedback.

Do insteadPressed feedback is the web's darkening (below), on both platforms, plus a light haptic on buttons. Android ripple is off by default; allow it only as an opt-in on ghost and list-row surfaces, colour rgba(255,255,255,0.10).

The web has no ripple. iOS has none either, so ripple-only feedback leaves iOS with nothing, and a ripple on top of the darkening doubles the feedback on pink and green.

D7 · Input error state

Prompt saysDesign the error state.

Do insteadThe field itself does not change. The error is a message under it in neon-pink, announced to screen readers. There is no red.

That is exactly the web: aria-invalid is set but unstyled, and every form reports errors as text-neon-pink under the field. Red is not in the palette, and a pink border would be indistinguishable from the focus state.

D8 · Type scale

Prompt saysHeading, body, caption using the web app's type scale.

Do insteadSize text with fluidFontSize(token, width) from packages/tokens using useWindowDimensions(). At the 390pt design width every style renders at its minimum.

The web scale is clamp(min, vw, max); at 390 each preferred value sits below its minimum (h1: 7vw = 27.3 < 28). Heading → display/h1/h2/h3, body → body/bodyStrong, caption → small/label.

D9 · Small button touch target

Prompt says(not mentioned)

Do insteadsm stays 40pt visually; add hitSlop {top: 2, bottom: 2} so the touch target is 44pt.

AGENTS.md here requires 44×44pt touch targets; the web's sm is 40px tall.
