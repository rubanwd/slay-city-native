SLAY CITY Native · single design reference

The Slay City design system

Source of truth for every design-related SCN ticket · values read from rubanwd/slay-city@beba39d · units are points at the 390pt design width (web px map 1:1) · dark only · generated by design/tools/build_index.py

§ How to use this document

For an agent implementing a ticket: read §1 Global rules first — they override anything a ticket prompt says about colours, dark mode, variant names, hover or ripple. Then open the section the ticket index points to. Implement what is written here; where the web and this file disagree, this file wins (each disagreement is listed in §12 with the reason).
  • Exact values only. Every colour is a token from @slay/tokens — never a raw hex in a component.
  • Web class names are quoted next to values (rounded-2xl, bg-white/5) so ports stay greppable against the upstream checkout (node scripts/fetch-upstream.mjs).
  • Copy (button labels, empty states) is UI chrome and is quoted verbatim. Learning content (words, missions, questions) is never hard-coded.
  • Older per-ticket references still exist and agree with this file: design/SCN-5/index.html (tokens + 6 primitives, with a JSON spec), design/SCN-56/index.html (6 more primitives + icon paths), design/SCN-58/ (icon and splash assets). This file merges them.

§ 1 · Global rules

#RuleDetail
G1Dark onlyNo light palette, no dark: variants, no colour-scheme detection. Background #111111 everywhere. (SCN-5 D1)
G2Tokens onlySeven brand colours + surface + the artwork.* namespace (§2.1). Every grey is white at an opacity. No raw hex in components; no red (errors are neon-pink).
G3Web namesKeep the web's component and prop names: SlayButton variant="pink|green|ghost", SlayCard variant="pink|green|cyan|purple|ghost", sizes sm|md|lg. Do not rename to primary/secondary. (SCN-5 D2)
G4One primary actionEach screen has exactly one filled call to action, full width, at the bottom of the content: lime-green lg for “go / continue” (Start, Next, Claim Reward, Let’s Go!), pink lg for auth submit, placement and retry. Secondary actions are ghost buttons, outline pills or underlined text.
G5Pressed, not hoverEvery web hover: style becomes the pressed style on native. Filled buttons darken (10% black overlay); outline/ghost surfaces get white/5–white/10. No Android ripple by default. (SCN-5 D6)
G6Touch targets ≥ 44ptVisual sizes stay as on the web (36pt circle buttons, 40pt sm button, compact wardrobe card buttons); add hitSlop so the touch target reaches 44×44.
G7Type scale at 390Use fluidFontSize(variant, width); at 390pt every variant is at its minimum. Raw Tailwind sizes (text-sm …) map to fixed points (§2.2).
G8Safe areasScreens pad the top inset; the tab bar owns the bottom inset. Full-screen flows (mission, reward, auth) pad both. Never a fixed 150px clearance — use the tab bar height. (SCN-56 D8)
G9Portrait, phone onlyorientation: portrait, supportsTablet: false. Layouts are a single 390-wide column; nothing above max-w-md (448) is designed.
G10Motion respects settingsEvery looping animation stops when Reduce Motion is on (useReducedMotion); entrances become instant. Animate transforms and opacity on the UI thread (Reanimated), not layout. (SCN-56 D10)
G11HapticsLight impact on every button press; success/error notifications on answer feedback (§2.8). Native-only addition.
G12English stays EnglishMission content, authored titles and level names are English. Only the parent console, the student profile + tab bar and the demo chrome are translated (en/uk/ru).
G13AccessibilityEvery icon-only button has an accessibilityLabel (web aria-label text is quoted in each section). Errors use accessibilityRole="alert"; progress uses progressbar with value. Focus rings are web-only and are not drawn.
G14Mascot is aliveSlay appears on map, mission loader, reward, wardrobe, profile and auth backdrop, and is always tappable where it bobs (hiss sound). Never static where the web animates it.

Tiles: radius 16 (12 for chips/letters, 8 for small keys), padding 20×16, gap 12. Answer reveal shows the correct tile and the wrong pick together. Feedback line under the tiles, 700 centred: lime “You got this! 🎉” / pink “Not quite — the answer is highlighted.” The primary action (green lg, full width, “Next” / “Finish Mission”) stays disabled until the task is answered or complete. Haptic: success on correct, error on wrong.

# 6.2 Forms

Column, gap 20 (auth) / 24 (onboarding) / 16 (teacher dialogs). Field = label + input (gap 6). Form-level error and status messages sit above the submit, centred 14/600 (pink error, lime status). Submit is the screen’s primary button (pink lg on auth, green lg on onboarding, green md in dialogs). Divider “or”: two white/15 hairlines with a label-style “OR” white/40 between, gap 12.

# 6.3 Lists & rows

Rows are “surface rows”: radius 16, border white/10, bg surface, padding 16×12, gap 8 between rows. Title bodyStrong white (truncate), meta small white/40–50, trailing status pill or chevron. Pressed: border white/20 (or the accent at /40 for teacher mission rows). Section heading above a list: label white/50, optional hint small white/35, 12 below.

# 6.4 Primary action placement

Game screens put the CTA at the bottom of the content (not floating): Map — in the bottom panel above the tab bar; tasks — after the tiles; Reward — last item; Welcome — bottom section with a ghost secondary under it. Console screens (teacher/parent) are information-first; their single action is a pill in the header (Homework) or a full-width green md button at the end of a list (Add Topic).
