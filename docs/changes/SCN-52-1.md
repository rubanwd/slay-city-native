# SCN-52-1 — Resolve upstream drift for the 7 flagged tracked files

> Type: task · Date: 2026-10-07

## Context

SCN-52 verified the Foundations (P3) exit criteria and found that
`npm run drift:check` reported 7 of the 48 files tracked in
`packages/core/.upstream.json` as drifted from upstream
(`rubanwd/slay-city`) since the last sync baseline (`21b4d87c`,
2026-09-17). Per the project's sync contract ([docs/SYNC.md](../SYNC.md)),
a tracked copy must never be hand-patched to fix drift locally — each
drifted file has to be resynced deliberately against the current upstream
content, with a judgement call recorded for anything genuinely adapted.
This ticket resolves that drift so the Foundations exit check can be
re-verified clean.

## What was done

1. Ran `npm run upstream:fetch` to refresh `./upstream` to its current head
   (`beba39d`), then `npm run drift:check` to get the authoritative list of
   drifted files — the same 7 files named in the ticket.
2. Diffed each drifted file against its upstream counterpart
   (`diff -u <local> upstream/<upstream path>`) to classify the change per
   `docs/SYNC.md` §4:
   - `packages/core/src/types/database.ts` and
     `packages/core/src/types/index.ts` — upstream added two new tables
     (`placement_test_attempts`, `placement_test_questions`), two new RPCs
     (`get_placement_test`, `submit_placement_test`), and two derived type
     aliases (`PlacementTestQuestion`, `PlacementTestAttempt`) for a new
     placement-test feature. Not adapted, logic changed → copied verbatim.
   - The four i18n message files (`messages.ts`, `messages/en.ts`,
     `messages/ru.ts`, `messages/uk.ts`) — upstream added placement-test
     copy (parent-dashboard card strings and profile-screen "take the
     test" strings) in English, Russian and Ukrainian, plus the two new
     type signatures in the `Messages` interface. Not adapted, logic
     changed → copied verbatim.
   - `packages/core/src/features/auth/roleRouting.ts` (`adapted: true`) —
     upstream's diff only touched `ensureRoleProfile` and
     `resolveHomePath`, which the manifest's existing note already
     excludes from this file ("take a Supabase client and belong in
     packages/data... A drift alert touching only those two functions does
     not affect this file"). Confirmed byte-for-byte that `roleHome()`,
     the one function this file carries, is unchanged between the local
     copy and upstream. Per `docs/SYNC.md` §4 rule 5 ("the change does not
     apply to mobile at all"), left the local file untouched and only
     updated its recorded hash.
3. Copied the 6 non-adapted files' content directly from the fresh
   `./upstream` checkout over their local counterparts.
4. Ran `node scripts/generate-upstream-manifest.mjs --upstream ./upstream`
   to recompute every tracked file's SHA-256 against the current upstream
   checkout and stamp the manifest's `syncedAt`/`syncedFrom` to the new
   baseline. This script hashes upstream content only (never the local
   file), so it was safe to run against all 48 entries at once — the 41
   already-in-sync files (including the other adapted file, `lib/hiss.ts`)
   got the same hash they already had, and only the 7 resynced entries'
   hashes actually changed.
5. Re-ran `npm run drift:check` — now reports `48 tracked files in sync`,
   synced from `beba39d` (2026-10-06T21:14:59.973Z).
6. Ran `npm run lint`, `npm run type-check`, and `npm test` — all pass
   (0 lint problems, 0 type errors, 263/263 tests across 28 files; the
   `upstream checkout not found` line in the test output is expected
   stderr from an existing CLI-argument test case in
   `scripts/check-upstream-drift.test.mjs`, not a failure).

## Technical decisions

- **`roleRouting.ts` hash updated without touching the file.** The
  manifest's own note (`adapted: true`, written when the file was first
  adapted) already states the rule for this exact situation: this file is
  intentionally only `roleHome()`; the other two functions upstream holds
  in the same path are data-access code that belongs in `packages/data`
  on this side, and a drift alert confined to those two functions doesn't
  apply here. Verified that read directly against the diff — `roleHome`
  is byte-identical locally and upstream; only `ensureRoleProfile` and
  `resolveHomePath` changed/were added upstream. This is `docs/SYNC.md`
  §4's rule 5 case ("the change does not apply to mobile at all") — update
  the hash, record why. The existing note already carries that
  justification, so it was left as-is rather than appended to.
- **Used `generate-upstream-manifest.mjs` instead of hand-editing hashes.**
  The script recomputes every entry's hash from the live upstream checkout
  and is the documented way (`docs/SYNC.md` §4, `scripts/
  generate-upstream-manifest.mjs`'s own header) to keep the manifest a
  reproducible artifact rather than hand-typed hashes. Running it against
  all 48 entries was safe and simpler than isolating the 7: it only reads
  upstream content, never the local files, so already-in-sync entries came
  back with identical hashes.
- **No genuine conflicts found.** All 7 files resolved cleanly under
  `docs/SYNC.md` §4's existing rules — none required a judgement call
  between upstream intent and a local customization, so nothing is flagged
  as an open question for this ticket.
