# SCN-1 — Set up repository structure and Expo project scaffold

> Type: task · Date: 2026-09-25

## Context

SCN-1 asked for the initial Expo + TypeScript scaffold for `slay-city-native`: the
`app/`, `src/`, `packages/`, `upstream/`, `scripts/`, `docs/` and `assets/` layout,
a root `package.json` with React Native / Expo Router / NativeWind / Reanimated /
TanStack Query / Supabase dependencies, EAS build configuration, `app.json` iOS and
Android metadata, TypeScript/ESLint/Prettier matching the web app's conventions, and
`upstream/` kept out of version control.

By the time this run started, prior work packages (WP-0.1 "Repository bootstrap and
snapshot" and WP-0.2 "packages/core", see `docs/WORK-PACKAGES.md`) had already landed
in commits `f3b5e04` and `290e8a5` and built almost all of this: the Expo Router app
shell, `packages/core|data|tokens`, `tsconfig.json` path aliases, `eslint.config.js`
layer rules, `.prettierrc`, the CI workflow, `scripts/fetch-upstream.mjs` /
`check-upstream-drift.mjs`, `.gitignore` excluding `upstream/`, and `UPSTREAM_BASELINE`
holding the seed commit. This run's job was to find and close the remaining gaps
against the ticket rather than re-scaffold a project that already exists.

## What was done

Audited the existing tree against every clause of the ticket and each `AC` in
WP-0.1/WP-0.2, and found two genuine gaps:

1. **No `eas.json`.** The ticket asked for EAS configuration and `AGENTS.md` already
   documents `eas build --profile preview` as a supported command, but no profile
   existed for it to use. Added a standard three-profile `eas.json`
   (`development` — internal distribution with a dev client, `preview` — internal
   distribution on a `preview` channel, `production` — auto-incrementing build number
   on a `production` channel), plus an empty `submit.production` block so
   `eas submit` has somewhere to read from later. No EAS project ID was set in
   `app.json`'s `extra.eas` field — that is written by `eas init`, which requires an
   authenticated Expo/EAS account this run does not have.
2. **TanStack Query was missing from `package.json`.** The ticket explicitly lists it
   alongside React Native, Expo Router, NativeWind, Reanimated and the Supabase
   client as a required dependency; the other four were already present. Added
   `@tanstack/react-query` and ran `npm install` to update `package-lock.json` in
   step (added 2 packages, no version changes elsewhere in the tree).

One clause of the ticket — "Create `UPSTREAM_BASELINE` as an empty placeholder
file" — was **not** applied; see Technical decisions.

Everything else the ticket asks for was already in place and was left untouched:
`app/`, `src/`, `packages/core|data|tokens/`, `scripts/`, `docs/`, `assets/`
directories; `app.json` with `bundleIdentifier: app.slaycity.mobile` (iOS) and
`package: app.slaycity.mobile` (Android); `tsconfig.json` with `@slay/core`,
`@slay/data`, `@slay/tokens`, `@/*` and `~/*` path aliases; `eslint.config.js`
enforcing the layer rules (no React/RN/Next/Supabase imports in `packages/core`, no
imports from `upstream/`); `.prettierrc`; `.gitignore` excluding `upstream/`; and
`.github/workflows/ci.yml` running lint/type-check/test plus a nightly upstream-drift
job.

## Changes by file

- `eas.json` — new. Adds `development`, `preview` and `production` EAS build
  profiles (per the ticket's "Set up EAS configuration" requirement) and an empty
  `submit.production` block. `cli.version` pinned to `>= 16.0.0`,
  `appVersionSource: "remote"` so EAS manages build numbers instead of `app.json`.
- `package.json` — modified. Added `@tanstack/react-query@^5.103.2` to
  `dependencies` (per the ticket's dependency list).
- `package-lock.json` — modified. Regenerated by `npm install` after the
  `package.json` change; additive only (2 packages added, nothing else changed
  version).
- `docs/changes/SCN-1.md` — new. This file.

## Technical decisions

- **Did not empty `UPSTREAM_BASELINE`.** The ticket says to create it as an empty
  placeholder, but WP-0.1 already gave it real content: the seed commit
  (`98327f5`) that `slay-city-native` was forked from. That value is load-bearing —
  `scripts/fetch-upstream.mjs --baseline` reads it with
  `readFileSync(BASELINE_FILE, "utf8").trim().split(/\s+/)[0]` and exits 2 if the
  file is missing or unparsable, and `docs/ARCHITECTURE.md`, `docs/CONCEPT.md` and
  `docs/RISKS.md` all document the file as holding the seed commit. Overwriting it
  with an empty file would silently break `npm run upstream:fetch -- --baseline`
  and contradict documentation that describes working, shipped behaviour. Since the
  ticket's instruction predates WP-0.1 having actually run and is now stale, the
  existing file was left as-is. Flagged below rather than silently ignored.
- **No EAS project ID.** `eas.json` itself doesn't need one, but a fully wired EAS
  setup usually also has `expo.extra.eas.projectId` in `app.json`, written by
  `eas init` against a real EAS account. That step needs credentials this run
  doesn't have, so it was left for whoever runs `eas init` interactively.
- **Did not re-scaffold anything already present.** Rather than regenerating
  `app/`, `packages/*`, config files, etc. from scratch (which risks conflicting
  with WP-0.1/WP-0.2's already-reviewed, already-tested output), this run treated
  the existing tree as authoritative and only filled the diff between it and the
  ticket.

## Data, API and configuration

- New dependency: `@tanstack/react-query@^5.103.2` (not yet wired into any screen —
  no `QueryClientProvider` exists yet; that's follow-on work, likely alongside
  `packages/data` usage in the app layer).
- New config file: `eas.json` (build profiles only; no secrets, no project ID).
- No schema, auth, or public API changes.

## How to verify

- `npm run lint` — passes, no errors.
- `npm run type-check` — passes, no errors.
- `npm test` — 184 tests passed across 16 files (unaffected by this change; run to
  confirm no regression from the dependency bump).
- `node -e "JSON.parse(require('fs').readFileSync('eas.json','utf8'))"` — confirms
  `eas.json` is well-formed.
- Manual: `eas build --list` or `eas build --profile preview --platform ios
  --non-interactive` (requires an authenticated `eas` CLI session, not available in
  this run) would be the next step to confirm the profile is actually usable.

## Limitations and follow-ups

- `UPSTREAM_BASELINE` was intentionally left as-is (seed commit, not empty) — see
  Technical decisions. If the ticket's "empty placeholder" requirement was meant
  literally, that needs a maintainer decision, since honoring it breaks
  `upstream:fetch -- --baseline`.
- No `expo.extra.eas.projectId` in `app.json` — needs `eas init` run by someone with
  EAS account access.
- `@tanstack/react-query` is installed but not yet wired up (no `QueryClientProvider`
  in `app/_layout.tsx`); wiring it in is out of scope for this scaffold ticket and
  belongs with the first screen that needs server-state caching.
- Two files were already modified in the working tree before this run started
  (`.gitignore` — adds the expo-cli-generated `expo-env.d.ts` ignore block;
  `tailwind.config.js` — sets `darkMode: "class"`) and were left untouched since
  they're unrelated to this ticket.
