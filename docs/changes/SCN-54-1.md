# SCN-54-1 — Decide SCN-54 scope vs SCN-5 D8 (SlayText) — resolve conflicting typography spec

> Type: task · Date: 2026-10-07

## Context

SCN-54 asked for Nunito font loading plus `Heading`/`Title`/`Body`/`Caption`/
`Label` typography components matching the web app's `typography.css`. SCN-5
(merged 2026-09-28, documented in `docs/changes/SCN-5.md`) had already shipped
font loading, the full `typeScale` in `packages/tokens`, and a single text
primitive, `src/components/ui/SlayText.tsx`, covering the same eight CSS
classes. The design reference's decision **D8** (`design/SCN-5/index.html`,
`<script id="slay-ui-spec">`) explicitly overrides a component-per-variant
split in favour of `SlayText` + `fluidFontSize(variant, width)`, because
static NativeWind classes can't reproduce the web's `clamp(min, vw, max)`
fluid sizing. A prior run against SCN-54 itself (`docs/changes/SCN-54.md`)
already found all of this and made no code changes, but left the ticket's
disposition ("closed as already-done, or re-scoped") as an open question for
a maintainer rather than a committed decision — that ambiguity is what this
sub-task exists to close.

## What was done

Re-read `src/components/ui/SlayText.tsx`, `design/SCN-5/index.html`'s D8
block, `docs/changes/SCN-5.md`, `docs/changes/SCN-54.md`, and
`vitest.config.mts`'s test-scope comment to confirm the prior findings still
hold, then made the decision the ticket asked for:

**Decision: Option 1 — close SCN-54 as superseded.**

- Font loading, the type scale, and the typography primitive that WP-1.2 and
  SCN-54 both describe are already delivered by SCN-5's `SlayText` +
  `packages/tokens` (`typeScale`, `fluidFontSize`, `fontFamilyByWeight`).
  `docs/changes/SCN-54.md` independently re-verified this by re-fetching
  upstream (`beba39d`) and diffing `typography.css` against `typeScale` line
  by line — no drift.
- The literal `Heading`/`Title`/`Body`/`Caption`/`Label` component split SCN-54
  specifies is the exact shape D8 rejected, and for a concrete, testable
  reason: a static NativeWind `className` can only match the web's rendered
  size at the one design width (390pt) the class's fixed value encodes, and
  will drift at any other device width — failing WP-1.2's own "match the
  web's rendered sizes within 1pt" criterion everywhere except that one width.
  `SlayText` avoids this because `fluidFontSize` evaluates the `clamp()`
  triplet against `useWindowDimensions().width` on every render. Building the
  component split anyway would mean carrying two competing typography APIs
  for the same eight CSS classes, with the new one strictly less accurate.
  Option 3 (override D8) was rejected for this reason — no product need
  surfaced that would justify accepting that accuracy loss and the API
  duplication.
- Option 2 (narrow SCN-54 to a `SlayText` render test and/or a
  font-weight-to-family audit) was considered and rejected as a *separate
  ticket's* scope, not this decision's output, because:
  - The font-weight-to-family mapping is already verified — `docs/changes/
    SCN-54.md`'s diff against `upstream/src/styles/typography.css` covers it.
  - A `SlayText` render test requires standing up a React Native
    component-rendering harness (`@testing-library/react-native` or
    `jest-expo`, with a native-module mocking strategy) that does not exist
    yet. `vitest.config.mts` itself documents this as an intentional,
    repo-wide deferral ("Screen tests arrive with the design system in M1"),
    not an incidental gap this ticket happened to leave. Deciding the
    RN test-runtime (library + config location) is a decision that affects
    every future UI-component ticket; bundling it into closing a single
    typography ticket would make that choice by accident rather than on
    purpose. It should be scoped as its own ticket when M1 is planned.
- No code changes follow from this decision — SCN-54's own research pass
  already confirmed the existing implementation satisfies the need. This
  sub-task's output is the decision itself and the record of it below, for
  SCN-54 to be marked done/won't-do pointing at SCN-5.

## Technical decisions

- Chose Option 1 (close as superseded) over Option 2 (narrow scope) because
  the two concrete candidates for a narrowed scope — a font-weight mapping
  audit and a `SlayText` render test — are either already done (the audit) or
  not this ticket's decision to make alone (the test-runtime choice, which is
  explicitly deferred to M1 project-wide). Narrowing SCN-54 to "wait for an
  M1 test-runtime decision" would just relabel the same open question under a
  different ticket number.
- Chose Option 1 over Option 3 (override D8) because no reason was found —
  in the ticket, the design reference, or the codebase — to accept a less
  accurate, duplicated typography system. D8's own rationale (static classes
  can't reproduce `clamp()`) is a correctness argument, not a style
  preference, and nothing in SCN-54 rebuts it.
- Did not attempt to post this decision as an external ticket comment — this
  repository's pipeline treats `docs/changes/<ID>.md` as the record of what
  an item decided and why (see this file's own instructions), and there is no
  ticket-system write tool available in this environment. A maintainer or the
  orchestrating pipeline should treat this file as that comment when closing
  SCN-54.
